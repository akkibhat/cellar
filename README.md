# Cellar

Two halves of one site, built while I was learning about wine properly and
writing down what I found.

- **Cellarbook** — 25 chapters across eight parts, weighted toward France and
  New Zealand, with a searchable glossary, a grape explorer, an aroma wheel, a
  guided tasting tool that writes the note as you go, and a journal.
- **Cellardoor** — the bottles: what is still here and what I have tasted, each
  with a photograph, the registry's tasting profile where there is one, and an
  estimated drinking window.

It is here in case it is useful to anyone else. Everything a reader enters is
kept in their own browser — nothing is uploaded and there is nothing to sign
in to.

## How far to trust it

I am not a wine professional. Sources disagree more than you would expect,
and several figures in wide circulation are simply wrong - a liver-metabolism
rate turns up in careful places with its units dropped, which describes a liver
that would need eight months to clear one glass. Where I could not settle a
question I have said so in the chapter rather than picked a side, and the
regional chapters say plainly which places I have drunk and which I have only
read about.

## Editing the writing

The prose lives as strings inside typed block arrays, which is the right shape
for the site and an awkward one for writing. So it comes out to Markdown, gets
edited there, and goes back in:

```bash
node scripts/export-chapters.mjs
```

Edit `_previews/chapters.md`, leaving the `<!-- anchors -->` alone, then:

```bash
node scripts/import-chapters.mjs --dry-run
```

```bash
node scripts/import-chapters.mjs
```

Only changed strings are rewritten, so the diff is the edits and nothing else.
Anything ambiguous - a missing anchor, a literal that appears twice - is
reported and skipped rather than guessed at. Tables and embedded tools export
read-only. `git diff` is the change tracking.

Then <http://localhost:3007>.

## Layout

| | |
|---|---|
| `app/` | Routes. `/` is the front door, `/course` and `/cellar` the two halves. |
| `lib/content/chapters/` | The 25 chapters, as typed data rather than markup. |
| `lib/types.ts` | The `Block` union every chapter body is built from. |
| `lib/config.ts` | Feature flags, and the table that names and colours the two halves. |
| `components/` | The shell, the tools, and the mark. |
| `_bottles/` | The bottle shots as cut, at full size. Git-ignored: `public/bottles/` is what ships. Reprocess with `scripts/optimise-bottles.py`. |
| `scripts/` | The chapter round trip, the cellar pull, and the tools that keep numbering and reading times derived rather than typed. |
| `_previews/` | Working documents, git-ignored. `chapters.md` is regenerated by the exporter. |

Content is structured data, not JSX: a chapter body is an ordered list of typed
blocks (`p`, `h`, `list`, `steps`, `table`, `note`, `unsure`, `quote`, `tool`),
so a table or an embedded tool can sit inline with prose without any HTML
parsing.

## State of it

Builds to 24 static routes. Quizzes and reading-progress are written but
switched off behind flags in `lib/config.ts` — this is meant to be read and
consulted rather than completed.

25 chapters across 8 parts, about 1h 20m of reading. Chapter numbering,
reading times and part order are all derived rather than typed: see
`scripts/renumber-chapters.mjs` and `scripts/reading-times.mjs`, which read
the order out of `lib/content/course.ts` and `lib/content/parts.ts`.

## Deploying

The build is a static export - no server, no API routes, nothing rendered
per request - so `npm run build` writes a plain `out/` that any host will
serve.

It goes to Cloudflare Pages at <https://cellar.pi.co.nz>. Connect the repo
in the Cloudflare dashboard and it builds on push:

| | |
|---|---|
| Build command | `npm run build` |
| Output directory | `out` |
| Node version | 20 or newer |

Building from the repo rather than from a working copy is deliberate: two
design previews in `public/` are git-ignored, so a repo build leaves them
out and a local one would ship them.

To push a build by hand instead:

```bash
npx wrangler login
```

```bash
npm run deploy
```

`public/_redirects` maps the chapter slugs that changed when the chapters
were merged onto their current addresses.
